# PLAN: AlphaFlux Web (alphaflux.net)

The whole plan for AlphaFlux Web, step by step. Sections are numbered
S1 to S8. Each build step names the TODO.md phase it maps to, and
every TODO item ends with the plan section it serves, so one item plus
one section is the whole job. When the plan changes, this file changes
first, then TODO.md follows. Facts only: what is decided is stated,
what is open is named as an open question. The end state this plan
serves is ENDGOAL.md; the platform end state it presents lives in
alphaflux-console ENDGOAL.md.

## S1: What it is

The marketing site at alphaflux.net: static HTML served by nginx,
generated by a Go program in this repository from one JSON content file
per page. It is the public face of AlphaFlux, the self-hosted platform
that runs a service business end to end (the platform itself lives in
alphaflux-console; the full overview lives in alphaflux-docs).

The site doubles as the feature specification. It describes the product
we intend to sell, including parts that are designed and not yet built,
and BUILD-MANIFEST.md, generated from the same content, is the honest
answer for where each page, section, and feature stands: LIVE, PARTIAL,
PLANNED, or N/A.

## S2: Architecture

The grid: content in, generator in the middle, plain static files out.

| Module | What it owns |
| :--- | :--- |
| `content/*.json` | One file per page; the source of truth for all copy |
| `content/_status.json` | Build status per page, section, and feature; feeds BUILD-MANIFEST.md |
| `build/` | The generator: Go, standard library only; also writes sitemap.xml, robots.txt, llms.txt, llms-full.txt |
| `assets/site.css` | The token layer and every component style |
| `assets/fonts.css`, `assets/fonts/` | Self-hosted faces, Latin and Latin Extended subsets |
| `assets/icons.svg` | The icon sprite; every icon is referenced by id from content |
| `assets/og/` | Open Graph card sources, rendered to PNG by scripts/make-og.sh |
| Generated pages (`*.html`) | Committed build output; edit content or the generator, never these |
| `default.conf` | nginx: clean URLs via try_files, cache policy, admin path passthrough |
| `Dockerfile` | The container: plain static files, no Go toolchain at build time |

## S3: Hosting (hosted from AlphaFlux, the platform front door)

This site is hosted from AlphaFlux itself. A push to main fires a
GitHub webhook into the Dokploy app on the home server; Dokploy builds
the Dockerfile and updates the swarm service, and Traefik serves it at
alphaflux.net. This container is also the public front door for the
platform: the routing file on the server points alphaflux.net at this
service, and its nginx proxies the console paths (/login, /console,
/api, /phone, /twilio, /scan, /patrol, /admin, /waitlist, /accept) to
the alphaflux-console app on port 8080 (see alphaflux-console
DEPLOY.md). Tenant websites are a console feature (the website
builder, alphaflux-console TODO T-7.3); this repo is the platform's
own site.

## S4: Step 1, generator, status ledger, and webhook hosting (TODO Phase 0)

The shipped base: the Go generator rendering content into committed
HTML plus sitemap and llms files, the honest status ledger in
content/_status.json feeding BUILD-MANIFEST.md, deploy on push, and
self-hosted fonts and icons. Static assets are compressed at build
time with zopfli from the harvest shelf, the smallest gzip output
being the right trade for files shipped to every visitor.

## S7: Step 4, the upkeep loop (TODO Phase 3)

OG cards regenerated with any copy change, the responsive check before
any page is called done, rail and sitemap and llms verification after
any new page, the Dokploy and Traefik notes kept true, and the terms
and privacy pages reconciled with the console Terms of Service when it
publishes. The site is also watched by the console side alerting
(alphaflux-console T-1.1), so an outage is heard about from the
platform, not from a customer.
