# RUNBOOK: AlphaFlux Web (alphaflux.net)

## Build
```bash
go run ./build
```
That reads content/*.json and writes the pages to the repository root, plus sitemap.xml, robots.txt, llms.txt, llms-full.txt, and BUILD-MANIFEST.md. The generated HTML is committed, so the container build needs no Go toolchain. Source of record: README.md in this repo.

## Run locally
The build output is plain static files in the repository root. The production shape is the Dockerfile in this repo: nginx serving those files with default.conf (clean URLs via try_files, cache policy, admin path passthrough). There is no application server and no database in this repo.

## Deploy
From README.md: committing to main updates alphaflux.net, nothing is built by hand.
```text
git push origin main
  -> GitHub webhook fires on push
  -> Dokploy deploy endpoint for this app
  -> Dokploy clones the repo and builds the Dockerfile
  -> swarm service alphaflux-web-qjojtn is updated
  -> Traefik serves it at alphaflux.net
```
Dokploy settings that must not drift: buildType dockerfile, dockerfile Dockerfile, buildPath /, autoDeploy true. Routing lives outside Dokploy in /etc/dokploy/traefik/dynamic/alphaflux-web.yml on the server, which names the swarm service with its suffix. To find the current service name: docker service ls | grep alphaflux-web.
Rollback: return the repo to the previous good commit and push; the same webhook path rebuilds and updates the service.

## Verify
- BUILD-MANIFEST.md regenerated by the build, with page statuses matching content/_status.json
- Run the responsive check before calling any page done: scripts/check-responsive.mjs (TODO T-3.2)
- After adding a page, verify the build wrote it into the rail, the footer, sitemap.xml, and both llms files (TODO T-3.3)
- Regenerate Open Graph cards with any copy change: scripts/make-og.sh, and commit the PNGs with the copy (TODO T-3.1)
- Live check: alphaflux.net serves the public pages, and the console paths proxy through to the console app

## Where things live
- Public site: alphaflux.net, Traefik at the edge, nginx in this repo's container
- Host: home server ubuntu-server, Dokploy app for this repo, swarm service alphaflux-web-qjojtn (name recorded in README.md)
- Routing file: /etc/dokploy/traefik/dynamic/alphaflux-web.yml on the server
- Console behind the door: alphaflux-console app on port 8080 (repo alphaflux-console, record in its DEPLOY.md)
- Credentials: secure vault and connector storage only, by entry name. The Dokploy deploy token lives in Dokploy's own app records. No credential values in this repo.

## Gotchas
- If the Dokploy app is ever deleted and recreated, the swarm service suffix changes and the Traefik dynamic file must be updated in the same move, or the site 404s at the edge while the container runs perfectly (fix: README.md deploy section; TODO T-3.4)
- A page slug can collide with an nginx proxy prefix: the phone slug collided with the /phone proxy prefix in 2026-09 (fix: commit 44adcae; check new slugs against the proxy list)
- Do not edit generated HTML, sitemap.xml, robots.txt, or llms files by hand (fix: edit content/*.json or the generator in build/, then run go run ./build)
- The build fails on a rail entry with no page, a duplicate slug, or an icon referenced in content that is not in the sprite (fix: correct the content or add the icon to assets/icons.svg)
