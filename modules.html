Turning a module on is a configuration change

There is no separate database per feature and no import step between them. A module is a view onto records the platform was already keeping.

That is why a company can start with the phone and the schedule, add dispatch three months later, and add fleet after buying its first truck, without any of it being a project.

It is also why reports stay honest as modules appear. The numbers were always being recorded, so history does not start over when a new module is switched on.

See the platform architecture

  • Registry driven

    Screens, permissions and limits all come from the module registry, so the interface matches what a company actually has.

  • Permissions do not grant themselves

    Turning on a module makes new permissions available. Someone still has to assign them, so nobody gains access by accident.

  • History is continuous

    A module that starts today reads work that was recorded before it existed. Nothing has to be backfilled.

  • Repackageable

    Because the catalogue is data, an operator running the platform under their own brand can define their own bundles and pricing.

Modules that pair well

Some combinations are the reason the platform exists. These are the ones companies turn on first.

  • Phone plus scheduling

    The agent answers, checks real capacity and books, so the schedule fills itself instead of waiting for office hours.

  • Field operations plus inventory

    A job draws down the technician's stock, and a low part is visible before the next job needs it rather than after.

  • Fleet plus reports

    Distance, on time percentage and jobs per technician come out of the same records the dispatcher is already using.

  • Billing plus agreements

    Recurring visits and recurring revenue are one object, so the invoiced amount and the booked work cannot drift apart.

  • Email plus CRM

    A campaign targets a real pipeline stage, and a reply lands on the account timeline rather than in a separate list.

  • Anything plus agent access

    Hand an agent a scoped key and it can work across modules under one set of permissions and one audit trail.

Questions people ask before signing up

Can I buy a module without the bundle around it?

Yes. Any module can be added to any plan as an add on, priced on its own. That is usually how a company moves up: it adds the one thing that is currently costing it money rather than changing plan.

What happens if I switch a module off?

It stops appearing and its operations stop being available. The records it produced are not deleted, and switching it back on restores access to all of it.

Is there a module for something you have not built yet?

The registry is open. New modules follow the same contract as the existing ones, so adding one does not disturb the others, and the interface picks it up without a redesign.

Do the modules share one database?

They share one data model, which is the point. Records are scoped to the company that owns them rather than to the module that created them, so the customer your phone module logged is the customer the dispatch board routes to.
