### How keys and scopes work  
**PARTIAL**

An integration is a credential with a job to do. Nothing about the design assumes a human holds it.

- [ ] **Scoped read and write** (PARTIAL) Access is granted per module, so an integration that books work does not need the billing module and does not get it.
- [ ] **Hashed and shown once** (PARTIAL) A key is displayed at the moment it is created and stored only as a hash. Losing one means issuing a new one, not recovering the old one.
- [ ] **Inherits its owner** (PARTIAL) A key carries exactly the permissions and companies of the account that created it, and cannot reach past them.
- [ ] **Revocable immediately** (PARTIAL) Disable a key and every request using it stops. Nothing else on the account is disturbed.
- [ ] **Optional expiry** (PARTIAL) A key can be issued with an expiry date for temporary or contractor access.
- [ ] **Every use is recorded** (PARTIAL) Actions are written to the audit trail against the account that owns the key, so a key is never anonymous.
